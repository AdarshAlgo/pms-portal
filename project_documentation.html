1. Executive Summary & Institutional Vision

In premier higher education engineering institutions, final-year capstone projects constitute the pinnacle of undergraduate and postgraduate research. They provide conclusive evidence of student competency across system architecture, mathematical modeling, hardware-software co-design, and team collaboration. Historically, capstone administration suffered from severe friction: evaluation subjectivity, delayed submission feedback, fragmented communication channels, and manual spreadsheet tallying of ABET/NBA accreditation criteria.

The Project Progress Monitoring & Evaluation System (PMS Portal v2.0) was conceptualized and implemented to eliminate these governance bottlenecks. By providing a unified, multi-tenant academic platform, the system digitizes the entire lifecycle of undergraduate research cohorts—from initial project proposal registration and milestone deliverable submission to criteria-based rubric scoring and accreditation analytics.

Strategic Alignment with UN SDG 9 (Industry, Innovation & Infrastructure):
The system provides foundational digital infrastructure for universities, promoting inclusive and sustainable technological education, enhancing scientific research, and establishing transparent performance audit trails.
Objective 1: Transparent VelocityBurndown
Real-time visibility into milestone completion velocity using weighted percentage metrics, preventing last-minute student scrambles and delayed project submissions.
Objective 2: Quantitative RubricsAccredited
Elimination of subjective grading through multi-tier criteria rubrics (Technical Rigor, Innovation, Code Quality, Viva Defense) aligned with international ABET outcomes.
Objective 3: AI Copilot GroundingVidya.ai
Local database-grounded intelligent assistant providing instant role-tailored queries, telemetry insights, and risk detection without external data leakage or hallucinations.
Objective 4: Complete TraceabilityTamper-Proof
Granular timestamped audit logs for every deliverable upload, rubric grading transaction, feedback comment, and administrative privilege change.

RBAC Implementation & Security Decorators

View functions utilize custom Python decorators located in app/routes/ to enforce access rules. Attempts to access prohibited endpoints result in immediate HTTP 403 Forbidden responses, which are logged to the central activity telemetry: 

# RBAC Enforcement Example in Flask Blueprint
@faculty_bp.route('/evaluate/<int:submission_id>', methods=['GET', 'POST'])
@login_required
@log_activity('evaluate_submission')
def evaluate_submission(submission_id: int):
    # Only Faculty Guide assigned to team OR System Admin can score
    submission = Submission.query.get_or_404(submission_id)

        abort(403)  # Block unauthorized student or peer faculty access

Modular Blueprint Breakdown

The application code is organized cleanly into functional blueprints located under app/routes/:

  • auth_bp (/auth): User sign-in, account registration, role auto-switch tabs, session termination, and 1-click test credential login.
  • admin_bp (/admin): Institutional governance, term management, department creation, global milestone calendars, rubric template creation, and live audit telemetry.
  • faculty_bp (/faculty): Team inspection desk, deliverable review inbox, quantitative criteria scoring calculator, and advisory meeting reports.
  • student_bp (/student): Project registration portal, milestone submission desk, burndown velocity curves, and faculty feedback audit trails.
  • vidya_bp (/vidya): API endpoints powering the embedded Vidya.ai copilot, action chips, and context-grounded responses.
  • api_bp (/api): Asynchronous JSON endpoints serving dynamic Chart.js feeds (/api/progress/<id>, /api/scores/<id>, /api/notifications).

6. Milestone Lifecycle & Sprint Governance Workflow

The academic calendar is divided into 4 structured milestone sprints, each commanding a specific weighting towards the scholar's final evaluation score:

Sprint Stage Deliverable Description Weightage Target Deadline Approval Gate
Milestone 1
Architecture		 Literature Review, Problem Formulation, Functional Requirements & Architecture Schematics. 20% Total Week 4 (Fall Term) Literature verification & guide clearance.
Milestone 2
Schema & Proto		 Relational Database Schema, ER Diagrams, Hardware Pinouts & Component Bench Testing. 25% Total Week 8 (Fall Term) Laboratory proof-of-concept clearance.
Milestone 3
Implementation		 Model Training, Production Source Code, Field Telemetry Logs & Sensor Calibration Data. 35% Total Week 12 (Fall Term) GitHub repository verification & test run.
Milestone 4
Final Defense		 Final Technical Report, Viva Presentation Defense before Academic Board & Video Demonstration. 20% Total Week 16 (Final Week) External evaluator panel defense.

Submission State Machine

Deliverables transition through four deterministic states governed by strict validation rules: 

[Pending Submission] ──(Student Uploads Code/URL)──> [Submitted]
                                                               │
                                                               ▼
[Approved & Scored] <──(Guide Awards Criteria Marks)── [Under Review]
         │                                                     │
         └──(Revision Triggered)──> [Revision Required] <──────┘
Weighted Burndown Mathematics: Total Project Completion % is calculated as:
Project_Progress = SUM(Milestone[i].weightage_percent * Status_Factor[i])
where Status_Factor = 1.0 for Approved milestones, 0.5 for Submitted/Under Review, and 0.0 for Pending.

7. Quantitative ABET / NBA Rubric Evaluation Framework

The cornerstone of the evaluation system is the accredited ABET Outcome Rubrics Matrix. Rather than arbitrary overall percentages, faculty guides score submissions across defined criteria dimensions:

Rubric Criterion Max Marks Weightage Scoring Rubric Dimensions
1. Technical Rigor & Architecture 40.0 Points 40% • Exemplary (36–40): Sound engineering design, minimal latency, modular code.
• Proficient (30–35): Functional design with minor architectural bottlenecks.
• Developing (20–29): Incomplete error handling; partial prototype.
• Unsatisfactory (<20): Critical conceptual flaws; non-functional code.
2. Problem Innovation & SDG Impact 30.0 Points 30% • Exemplary (27–30): Novel formulation, clear commercial or social SDG 9 impact.
• Proficient (22–26): Solid application of existing algorithms to new problem.
• Developing (15–21): Derivative work with limited novel contribution.
• Unsatisfactory (<15): Generic tutorial replication without innovation.
3. Documentation, Code Quality & Viva 30.0 Points 30% • Exemplary (27–30): Clean PEP-8/ISO code, full test coverage, confident defense.
• Proficient (22–26): Well-commented codebase, comprehensive report.
• Developing (15–21): Inadequate documentation, poor formatting.
• Unsatisfactory (<15): Undocumented code, unable to answer viva inquiries.

Grading Scale & Algorithm

The normalized evaluation percentage determines the permanent institutional grade:

A+ (90.0% – 100.0%) A (85.0% – 89.9%) B+ (80.0% – 84.9%) B (75.0% – 79.9%) C (60.0% – 74.9%) 
# Evaluation Algorithm (app/services/evaluation_service.py)
total_obtained = sum(criterion_marks.values())
total_max = sum(criterion_max.values())
percentage = (total_obtained / total_max) * 100.0

if percentage >= 90.0:   grade = 'A+'
elif percentage >= 85.0: grade = 'A'
elif percentage >= 80.0: grade = 'B+'
elif percentage >= 75.0: grade = 'B'
elif percentage >= 60.0: grade = 'C'
else:                   grade = 'F'

8. Embedded Vidya.ai Intelligent Copilot

The platform features an embedded institutional intelligence agent named Vidya.ai (v2.0 PRO), engineered to assist faculty and students through contextual, role-aware database grounding.

Zero HallucinationGrounded
Unlike public LLM wrappers, Vidya.ai executes verified SQL queries directly against the local SQLite database, grounding all responses in live institutional telemetry.
RBAC Security ShieldProtected
Queries are filtered through the user's role session. Students are restricted from querying private faculty evaluations, mentor notes, or other teams' confidential scores.

Interactive UI Drawer Specifications

In response to user feedback, the Vidya.ai interface was re-engineered:

  • No Horizontal Overflow: Message bubbles utilize overflow-hidden break-words max-w-full preventing horizontal scrollbars on laptop displays.
  • Resizable Viewport: Includes a dedicated toggle button enabling instant expansion from Compact Mode (380px × 520px) to Medium-Large View (620px × 640px) for reading detailed reports.
  • 1-Click Action Chips: Contextual shortcut buttons dynamically populated based on user role (e.g., "Inspect At-Risk Projects" for Admin, "Pending Grading" for Dr. Verma, "Next Deadline" for Adarsh Katiyar).
  • Global Keyboard Shortcut: Instantly summonable from any dashboard using Ctrl + K or Cmd + K.
